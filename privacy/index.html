DayLog/Product notes

Privacy model

Temporary audio. Durable private memory.

DayLog is built around a simple privacy distinction: raw audio is sensitive and should be temporary by default; useful memory comes from transcripts, summaries, decisions, and searchable context.

Raw audio is not the product.

Long-term storage of every sound in a person’s life is unnecessary, uncomfortable, and hard to justify. DayLog should not be designed as an archive of raw audio. It should use audio as a temporary signal that can be transformed into useful private memory.

Transcription is the durable layer.

Text is easier to search, summarize, organize, delete, export, and reason over. The durable layer should be transcripts and derived memory: journal entries, decision trails, tasks, timelines, and context links.

The default should be: keep the meaning, not the microphone feed.

On-device transcription matters.

Local transcription is not just a technical feature. It is a trust feature. If private speech can become useful text without defaulting to the cloud, the product becomes more acceptable for daily use, sensitive moments, and long-running capture.

Cloud should be explicit.

Some future features may benefit from sync, backup, or more powerful models. But those should be visible choices, not hidden assumptions. Users should understand what leaves the device, why, and how to disable it.

Design principles.

  • Raw audio is temporary by default.
  • Transcripts and memory are the primary long-term artifacts.
  • On-device transcription is a core product promise where feasible.
  • Retention, export, deletion, and sync should be clear controls.
